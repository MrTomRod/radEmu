# Small doc and code details in radEmu and fastEmu

None of these are urgent; each radEmu item was checked against radEmu `339e3a7` and each fastEmu item against fastEmu `4695b88`. The radEmu items are on the fork branch [`small-things`](https://github.com/MrTomRod/radEmu/tree/small-things) ([diff](https://github.com/MrTomRod/radEmu/compare/339e3a774d8047a78b0e722137b8c4164ffae728...small-things)); the fastEmu items are documentation suggestions only.

- **`tolerance` default vs docs:** `emuFit` documents `1e-3` ([`emuFit.R#L40-L41`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/emuFit.R#L40-L41)), while the function default is `1e-4` ([`emuFit.R#L152`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/emuFit.R#L152)); the branch documents `1e-4`.
- **`pseudohuber_median` stopping criterion:** Stopping at `|Δy| < 1e-8` left up to `3.8e-6` error from the converged value (`tolerance = 1e-14`) across 2,000 random vectors ([`repro/ph_median.R`](repro/ph_median.R), [`pseudohuber_median.R#L26-L62`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/pseudohuber_median.R#L26-L62)); left unchanged, because that error is far below the `1e-3` the null fits allow for the constraint and reaching it would cost 1.5–2.3× the iterations of a function evaluated inside every null-fit iteration.
- **`dplyr` only in `Suggests`:** `emuFit` calls `dplyr::full_join` when zero-comparison parameters are flagged ([`emuFit.R#L782`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/emuFit.R#L782)), which fails if `dplyr` is not installed ([`DESCRIPTION#L28`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/DESCRIPTION#L28)); the branch uses base `merge(..., all = TRUE)` and restores the original row and column order (identical output on the cases that trigger it).
- **Discrete fallback message:** If the discrete null fit fails to converge, `score_test` prints `"Constraint sandwich algorithm ... did not converge"` ([`score_test.R#L260-L268`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/score_test.R#L260-L268)), naming the wrong solver; the branch names the discrete algorithm in both fallback messages.
- **Negative `Y` accepted silently:** `Y` is documented as nonnegative ([`emuFit.R#L3`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/emuFit.R#L3)), but `emuFit` ran without error or warning when a cell was negative and returned plausible-looking estimates (one cell set to `-30` moved that taxon's estimate from `-0.06` to `0.48`; [`repro/negative_y.R`](repro/negative_y.R)); the branch stops in `emuFit_check` with a message that names CLR- or log-ratio-transformed input.
- **Firth penalty vs the scale of `Y`:** With `penalize = TRUE` the penalty adds at most `0.5` per cell in `Y`'s own units, so coverage or proportion inputs (most nonzero values below 1) are dominated by it, and inputs rescaled by `1e5` or more weaken it on separated taxa, with no warning either way; the branch warns in `emuFit_check` when the median nonzero value of a penalized `Y` is below 1 (non-integer input) or above `1e5`, and documents the scale dependence in `?emuFit`.
- **`tol_discrete` is an absolute score tolerance:** The discrete null fit stops on the root mean score in `Y`'s units, so at `1e6`-fold scales it chases a relative score of about `1e-11`, stalls at the floating-point resolution of the log-likelihood, fails its line search, and falls back to the slower augmented Lagrangian algorithm; the branch floors the threshold at `sqrt(.Machine$double.eps) * mean(group total)`, which is inert for count-scale data, and a test checks that the fit converges again at `1e6`.
- **`max_abs_B` not forwarded when `penalize = FALSE`:** `emuFit` called `emuFit_micro` without `max_abs_B` ([`emuFit.R#L292-L300`](https://github.com/statdivlab/radEmu/blob/339e3a774d8047a78b0e722137b8c4164ffae728/R/emuFit.R#L292-L300)), so estimates were silently clamped at `emuFit_micro`'s own `50` while the near-boundary warning checked `0.9 * 250` and never fired; the branch forwards `max_abs_B`, so user-supplied values are respected and the warning checks the boundary actually in effect.

## fastEmu documentation

- **When exact `emuFit` is preferable:** For small `J` (fewer than a few hundred taxa) exact `emuFit` is fast enough and the approximation can diverge from it — on `wirbel_otu_small` (`J = 47`, default reference-set size 30) the fast and exact p-values have a Spearman correlation of 0.78 ([`repro/wirbel_fast_vs_exact.R`](repro/wirbel_fast_vs_exact.R)); the supplement targets `J ≥ 250` (§2.1), which the `fastEmuFit` documentation could say.
- **`constraint_diff` as a quality check:** `fastEmuFit` returns `constraint_diff` ([`fastEmuFit.R#L438-L440`](https://github.com/statdivlab/fastEmu/blob/4695b88b0a621cff2e2eb94ed7ca0fab223203af/R/fastEmuFit.R#L438-L440)), the gap between the reference-set median and the all-taxa median, which the supplement (§5.6) ties to approximation quality; the documentation could mention it as a value to inspect.
- **Reference-set size default:** `chooseRefSet`'s documentation says the default reference-set size is 50 ([`chooseRefSet.R#L6-L8`](https://github.com/statdivlab/fastEmu/blob/4695b88b0a621cff2e2eb94ed7ca0fab223203af/R/chooseRefSet.R#L6-L8)), while `fastEmuFit` uses 30 ([`fastEmuFit.R#L12-L14`](https://github.com/statdivlab/fastEmu/blob/4695b88b0a621cff2e2eb94ed7ca0fab223203af/R/fastEmuFit.R#L12-L14)) and `chooseRefSet` has no default; the two could agree on one number.
